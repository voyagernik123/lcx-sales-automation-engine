# W5 · SIGNATURE — the deck plate

`live.png` is the gate. Three GL variants and one CSS control, at the deck's real proportions.

## The finding

**The GL layer earns its bytes, and the first capture said the opposite.**

Run 1 used 300px-tall cells. At that 4.9:1 aspect the composite's vignette —
`smoothstep(0.12, 1.0, length(d * vec2(1.0, 1.45)))` — is dominated by the x term, so the
falloff degenerates into horizontal bands. Panel 2 showed a hard step the CSS control did not
have, and the honest conclusion from that image was **delete this**.

That was an artefact of the TEST, not of the surface. The deck is a tall page, not a strip.
Re-captured at 760px the banding is gone and the comparison inverts: the GL plate is a smooth
luminous field with a soft off-centre falloff, and the CSS control is visibly flatter — a dark
rectangle with a slight lift. The difference is real, and it is subtle by design; a backdrop
that announces itself is a worse backdrop.

**A capture at the wrong aspect ratio is as misleading as no capture at all.** This is the third
time in this program that looking at the output changed the answer — after P0's silent black
frame and the axis labels four suites passed. It is also the first time the *harness* was the
thing that lied.

## What it is

`apps/web/src/components/command/SignatureBackdrop.tsx`. No new shader and no spine growth: the
existing `pipeline.resolve` composites `plate + scene + bloom` and tone maps the sum, so an
empty scene target makes the plate and its vignette the entire frame. `bloomGain: 0` — there is
no highlight to bloom, and a gain would only lift the gradient's own quantisation noise.

Why not CSS: a CSS gradient interpolates in sRGB, which bands across a large near-black field
and muddies the midpoint. The same gradient built in linear light and tone mapped once does not.
Near-black is most of a dashboard, so this is where it matters.

## Cost

> machine-readable mode, so nothing keeps this table true. The `initial JS` row is already
> provably **~31 KB** out of step with that guard's own header — see below.

| | before | after | ceiling |
|---|---|---|---|
| `CommandDeck` chunk | 48.17 KB | 50.02 KB | 440 |
| initial JS | 839 KB | 839 KB | 850 |

Lazy-loaded, so the initial-JS headroom is untouched. No budget raise was needed —
`PLATFORM_VFX_100X.md` §8.3 reserved that decision for the owner and measurement retired it.

**Not generated, 2026-08-13, and this is why.** `docs/3d/p1/build.mjs`, `docs/3d/p0/measure.mjs`
and `docs/3d/w1/build.mjs` all now generate their published byte figures into fenced regions and
fail if the document and the bundler disagree. This table cannot join them yet, because the
generator that owns these numbers cannot be read by a script and adding that mode means editing
`apps/web/scripts/check-bundle.mjs`, which this track does not own. Transcribing a fresh number
here instead would just restart the clock on the same defect — the same call W1 made on
2026-08-13 and for the same reason.

What is already wrong, as evidence that the clock has run out rather than as a hypothetical:

- **`initial JS 839 KB` disagrees with the guard, and the gap grew while this note was being
  written.** `check-bundle.mjs`'s header carries its own hand-written records of the same
  measurement: **835 KB, 15 KB from the ceiling** at `:67` (corrected 2026-08-07, four days
  before this table), **830 KB** at `:81`, and — added by commit `830d8e6` on 2026-08-13, the
  same day as this note — **`839 → 808 KB (headroom 11 → 42 KB)`** at `:108`. So this page's
  839 is that commit's BEFORE figure, the `after` column is ~31 KB out, and "the 11 KB of
  initial-JS headroom" (which this page said until this edit) is now 42.

  Four hand-written records of one number, in two files, spanning 31 KB, with nothing
  reconciling them. **None of them is adopted here**, deliberately: copying 808 in would make
  this table current for exactly as long as it takes the next chunk to move, which is the whole
  defect. The reader cannot tell which is live and neither can I without a build, which this
  track is not permitted to run.
- **`before 48.17 KB` can never be regenerated by anything.** It is the `CommandDeck` chunk as it
  stood before `SignatureBackdrop` landed, so it is archival by nature. When this table is wired
  up, that cell must stay pinned and be labelled as archival; only the `after` column can be live.
- **`50.02 KB` is not a figure `check-bundle.mjs` prints.** It reports the single LARGEST chunk and
  the initial set; it has no per-chunk lookup, so this number came from reading `dist/assets` by
  hand. Chunk filenames are content-hashed, so any wiring must match `CommandDeck` by **prefix**.

### The exact addition that would unblock this

`check-bundle.mjs` already discovers everything needed; it only lacks a way to hand it over. A
`--json` mode would be enough — modelled on `docs/3d/p1/build.mjs --json`, which exists for the
same reason. **Insertion point, checked against the file rather than described loosely: between
`const pageChunks = …` (`:324`) and the summary `console.log` (`:326`).** That is the first point
at which every field below is in scope (`jsFiles` `:191`, `failures` `:261`, `initialJsKb` `:272`,
`cssKb` `:281`, `fontKb` `:287`, `passthroughKb` `:308`) *and* all four checks have finished
pushing to `failures` — the last of them is the passthrough check at `:309`. Placing it any
earlier emits a `failures` array that is missing failures.

```js
// apps/web/scripts/check-bundle.mjs — addition, not a rewrite.
// Under --json, stdout is somebody's JSON.parse, so the human summary and the two
// console.warn lines below must be routed through a no-op. p1/build.mjs does this with
// `const say = JSON_MODE ? () => {} : console.log`; without it the block is unparseable.
if (process.argv.includes('--json')) {
  console.log(JSON.stringify({
    generatedBy: 'apps/web/scripts/check-bundle.mjs',
    budgets: { MAX_CHUNK_KB, MAX_INITIAL_KB, MAX_BLOCKING_CSS_KB,
               MAX_PRELOADED_FONT_KB, MAX_PASSTHROUGH_KB },
    // Every chunk, not just the largest — a named-chunk figure like CommandDeck's is
    // unobtainable from the current output. Filenames are content-hashed; consumers
    // must match by prefix.
    chunks: jsFiles.map((f) => ({ file: f, bytes: statSync(join(ASSETS, f)).size })),
    initialBytes: { js: initialJsKb * 1024, css: cssKb * 1024, fonts: fontKb * 1024 },
    passthroughBytes: passthroughKb * 1024,
    failures,
  }, null, 2));
  process.exit(failures.length ? 1 : 0);
}
```

Bytes rather than the KB floats the script carries internally, for p1/build.mjs's reason: a
consumer that receives `48.17` cannot tell rounding from measurement. The `* 1024` above looks
like it reintroduces the float it is meant to remove, and does not: `kbOf` is `statSync(…).size /
1024`, and multiplying or dividing a float64 by a power of two only shifts the exponent, so the
integer byte count comes back exactly. Any other unit — a `/ 1000` anywhere in the chain — would
not survive the round trip, which is the reason to say this out loud rather than leave the next
reader to assume either way.

With that in place the pipeline is a build away, and the build is the reason this is not being
done here — this track may not run one:

```bash
npm run build -w @lcx/web
node apps/web/scripts/check-bundle.mjs --json > /tmp/perf.json
node docs/3d/w5/build.mjs --write   # reads /tmp/perf.json, fills a gl-budget:begin w5-cost fence
```

`docs/3d/w5/build.mjs` is also not this track's file, so the consumer half is unwritten too.

## Fallback

`useFlatChart` starts `refused`, so SSR, print, no-WebGL and the first paint all get the CSS
plate underneath. `br-no-print` removes it from the board pack, which prints on white where a
dark plate is nonsense. Nothing on the deck is unreadable without this layer — that property is
what made shipping it safe.
